# Morocco AI CRM · 摩洛哥智能客户翻译助手

## v0.3.12：智库归类、模糊匹配与精准优先

智库搜索、右侧手动查价、当前聊天自动匹配和智能提取后的检索共用同一套排序：产品名称精准命中在前，同义别名和相近名称其次，同类历史记录随后。例如搜索“花洒”先显示花洒及淋浴喷头，再显示水龙头、卫浴五金及其他五金；搜索“五金”或“quincaillerie”可以查看该类全部已归档询价。支持常见中英法产品别名、中文前缀和有限拼写容错。右侧每次显示8项，可点“继续查看相似记录”逐批查看全部结果，不额外调用模型。

类目按产品名称和明确的产品别名推导，显示为“归类参考”。包含五金及卫浴/锁具/紧固件等子类，以及机械设备、电子数码、家具、服装纺织、鞋靴、箱包、包装、厨具、灯具等常见类目。仅有“铁制”“不锈钢”等材质或地址里的关键词不会把其他商品归为五金；类目与别名表是可扩展的常见词规则，不保证覆盖所有新品、品牌或任意错别字。可以在原有产品别名字段补充明确类目词，再按原流程人工校对。

分类和匹配在检索时计算，无需重新导入历史记录，不修改货物原文、HS、价格或报价关联。卡片区分“精准匹配”“同义产品”“同类参考”，同类价格仍属于原产品，不能直接当作当前询价报价。群、报价状态和分页过滤保留；聊天自动提取仍只读取当前客户当前票，确定性的归类检索不调用模型。原有人工审核、待核对标记与内部资料排除规则保持。

为 Barsan International Freight Forwarding 的中国—摩洛哥货代业务开发的私人客户沟通工作台。把截图或客户原话交给千问，得到中文翻译、三种回复参考及有来源的客户记忆。**这是可运行的本地首版，真实 AI 效果需配置百炼接口后验证。**

## 快速启动（Mac / Windows / Linux）

1. 安装 **Node.js 24 或更新版本**（官方：https://nodejs.org/）。
2. 解压源码，打开终端，进入 `morocco-ai-crm` 文件夹。
3. 执行 `npm start`，浏览器打开 http://127.0.0.1:3000 。本项目无第三方运行依赖，不需要 `npm install`。
4. 点击“体验固定示例”，检查审核、客户建档与15CBM→20CBM的历史保留。演示为明确标注的固定内容，不会识别真实截图。

Mac 示例：

```bash
cd ~/Downloads/morocco-ai-crm
npm start
```

若已经在文件夹中，只需 `npm start`。停止服务用 `Ctrl+C`。

## 接入真实千问

网页登录后点击右上角 **千问 API 设置**，或打开部署网站的 `/#settings`。粘贴API Key，选择创建Key的百炼地域；必要时展开“模型与接口地址”填写已开通、支持图片和JSON输出的模型ID或工作空间专用地址。点击“测试连接”会用一条简短法语文本验证真实调用及结果结构，不创建客户或草稿；测试产生少量模型调用用量。点击“保存设置”立即生效，无需重启。

Key不回显，不写入浏览器存储、日志、客户导出或数据库。网页设置以权限600的私有文件 `DATA_DIR/qwen-settings.json` 保存，重启后保留并覆盖下方环境配置。当前备份包含客户数据库、公共资料库和截图，不包含此密钥文件；恢复到新服务器后重新填写Key。未登录或跨站请求不能读写设置。当前设置只允许百炼官方HTTPS兼容地址。

也可使用服务端环境变量配置：

把 `.env.example` 复制为 `.env`，在本机文本编辑器填写：

```dotenv
DASHSCOPE_API_KEY=你的百炼密钥
DASHSCOPE_BASE_URL=从百炼控制台复制的兼容接口基础地址
QWEN_MODEL=qwen3.7-plus
```

- 北京工作空间示例：`https://你的工作空间ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。程序自行追加 `/chat/completions`，基础地址不要重复附加。
- 账号地域、工作空间、API Key 与模型权限必须对应。实际模型ID以控制台为准；可改为已开通的其他**支持图片与 JSON 输出**的千问模型。
- 当前默认以一个多模态模型完成识别、翻译和分析；独立OCR模型是后续增强，不是首版必需依赖。
- 网页保存后立即生效；环境变量配置需重启服务。接口状态“已配置”只说明配置存在；“测试连接”可验证文本调用，截图识别和翻译质量仍需真实样本验证。
- **不要把密钥发到聊天里。** 不会在前端、客户导出或源码中保存密钥。
- 真实分析会把所上传截图和选定客户的有限历史上下文发送到你配置的百炼接口；固定演示不会外发。程序没有其他第三方统计脚本。

官方参考（2026-10-14核对）：

- [Qwen3.7-Plus 模型](https://help.aliyun.com/zh/model-studio/qwen3-7-plus)
- [视觉兼容接口](https://help.aliyun.com/en/model-studio/qwen-vl-compatible-with-openai)
- [结构化输出](https://help.aliyun.com/en/model-studio/qwen-structured-output)

## 日常使用

1. 选已有客户，或先不选客户、上传后新建。**同名客户不会自动合并。**
2. 上传、拖入或 `Command/Ctrl+V` 粘贴截图；也可输入客户原话。一次最多10张，单张8MB，总计32MB，仅PNG/JPEG/WebP。
3. 点击“分析并翻译”。多张截图会按上传顺序逐张完整转录、逐条翻译，再统一生成摘要、事实与回复；只对相邻连续重叠消息保守去重，不省略单独短句。任一图片失败、无可读消息或输出被截断都会报错，不保存部分草稿。多图会增加模型调用次数和等待时间，图片请按聊天先后顺序上传。尚未配置接口时，明确提示配置，不伪造识别。
4. 在审核窗口确认客户归属、消息发送方、原文及中文，再选择要保存的事实。AI推测默认不勾选。
5. 保存后在聊天区查看原文/翻译，在右侧查看客户事实和历史来源，选择“专业商务 / 自然友好 / 简短直接”回复并复制。
6. 不确定时关闭审核即可，草稿会保留，可从“待审核草稿”恢复。

每次模型读取该客户的当前事实、最近20条消息和关键词匹配的最多8条较早记录。**客户之间不共享上下文**。聊天重启后保留，源码更新时不要删除 `data/`。

## v0.2.2：自定义多语言回复与记忆总结

在“AI 回复参考”点击“自定义回复”，输入中文，勾选英语、法语、阿拉伯语、摩洛哥达里贾或西班牙语（可同时选择多种），点击“翻译回复”。千问会忠实翻译你的原话，每种语言各有“复制”按钮，不会自动发送，也不会写入客户档案。修改中文或目标语言后旧翻译会清除；不同客户及运输需求的输入和结果分别保留在当前页面中。

右侧上半部分为“全部记录的记忆总结”：根据当前客户全部已归档的有效事实自动整理成段落，按未分类沟通和各票运输需求分开，不受聊天搜索或当前所选票限制；已取代及待复核事实不作为当前记忆，仍可展开查看来源和历史。此汇总来自已审核事实，无需额外模型调用。

下半部分为“本次聊天图片总结”，只显示当前所选范围本次分析的摘要。尚未归档时标记待确认，上方正式记忆不变；归档后更新全部记忆。来源有变更时停用旧摘要，避免继续把它当成当前结论。客户资料、运输需求、报价及历史来源保留在下方可展开区域。

## v0.2.3：回复区收起与双语记忆

“自定义回复”后的小箭头可临时收起整个回复正文，扩大聊天区域；再次点击展开，中文输入、目标语言和已完成翻译保留。收起期间模型返回也不会自动展开；刷新页面恢复默认展开状态。

总记忆逐项显示资料原文和中文解释。已是中文的记忆直接配上来源消息原文；旧外文或混合语言记忆会通过已配置的千问补中文，不修改原事实、原消息或归档摘要。首次查看需要补译的内容会产生少量模型调用；中文解释在当前服务进程内缓存，重启服务后可重新整理，不用重新上传截图。来源或记忆版本变更时旧译文不再使用。翻译失败会保留原文并显示重试按钮。

## v0.2.4：所有聊天共用的数据库参考

点击“AI 回复参考”标题旁的 **数据库参考**，新增、编辑、搜索、停用或删除公司介绍、类目佣金/费率、服务说明和其他资料。这里由你们手动维护，所有客户聊天共用，不从客户私有记录自动汇入。佣金/费率必须写明适用类目和条件，可补充关键词（含中文、英文或法语别名）及有效期。“内部查阅”资料只供你查看，不发送给模型生成客户回复；停用或过期的资料不参与生成。

真实聊天分析先完成识别，再根据识别内容和当前运输需求匹配相关公共条目，连同完整适用条件生成三种回复。每次最多提供8条、合计32000字符的资料，优先匹配关键词、标题、适用条件及通用公司/服务说明；不截断费率条目的条件。公共资料不进入客户事实，佣金不直接等同于运费或已确认报价，缺少计算基数、币种等条件时应先澄清。模型实际引用的资料可在回复下方点击查看，复制仍需你核对，不会自动发送。

已有聊天可点 **按资料库更新回复**，无需重新上传截图，不改变原消息、事实或本次摘要。资料有修改、删除或过期后，旧自动回复会提示更新并停用复制；原聊天本身有校对变更时仍需重新分析。自定义回复只翻译你的输入，不混入公共资料。

资料保存在同一数据目录下的 `company-knowledge.sqlite`，与客户数据库分开。备份现在包含客户数据库、公共资料库及截图；恢复时同时恢复两个数据库。资料库初始为空，不预填任何公司介绍或价格。

## v0.2.6：右侧回复与客户记忆入口

“AI 回复参考”整个模块移至右侧，包括三种回复、自定义多语言翻译、数据库参考、来源与复制。中间区域专用于聊天记录和上传。手机工作区导航改为“客户 / 对话 / 回复”，切换保留当前回复草稿。

左侧每位客户条目右侧新增“记忆”按钮，点击弹窗查看该客户的全部记忆、双语解释、消息来源、本次摘要、历史和待复核信息，以及运输需求、报价和导出。可以查看其他客户的记忆，同时保留当前聊天、所选运输需求和回复草稿。窗口内的运输需求选择只改变窗口的摘要与报价范围，全部记忆仍覆盖该客户所有已归档记录；数据仍按客户与运输需求隔离。

## v0.2 增加：多票货物与报价

- 每位客户可以新建多票运输需求，分别保存消息、货物事实与报价；客户联系方式和沟通语言继续共用。
- 聊天区上方选择运输需求后再分析。模型只读取该票的货物事实、消息和报价；“未分类”只读取未分类记录。
- 审核时确认本批消息归属，也可同时新建客户及运输需求。一批消息只能归属一票；混合多票的截图应分批审核。更改分析时的运输需求会停用旧回复，重新分析后再复制。
- 档案里可手动记录金额、币种、报价范围、有效期、状态和本票消息来源。不会计算或发送报价；修订时新增记录，旧金额保留。
- 来源消息修改或删除会使对应报价待复核并退出有效AI上下文。新报价或需求备注变化后，该票旧回复停用。
- 数据库自动由v1升级到v2，旧消息、事实、草稿、截图及去重记录保留在未分类。迁移前请先停止旧应用并备份。

## 核心功能

- 类微信的三栏聊天界面与手机客户/对话/档案切换。
- 客户创建、搜索、编辑；消息全文搜索、校对、删除；客户文字档案JSON导出。
- 多图/文本千问调用、结构校验、超时和上游错误提示。
- 人工审核草稿、客户身份确认、中文翻译与原文、三种回复参考。
- SQLite持久化记忆，关联原消息和截图；明确陈述/推测/历史/待复核状态。
- 同截图重复导入与相邻连续重叠消息的保守去重；孤立短消息不跨历史误删。
- 消息变更后关联记忆待复核、旧回复停用；原截图仍可查看。
- 可选密码登录、同源检查、Host限制、内容安全策略及备份脚本。

## 实际限制

- **真实千问调用尚未在交付环境验证**：没有用户密钥，测试使用固定示例和本地模拟接口。Darija/Arabizi准确性必须用你的真实聊天样本校对。
- v0.2 已在 Chromium 验证桌面和390px手机布局，以及运输需求/报价切换。不同手机系统、截图粘贴、剪贴板授权及真实业务样本仍需使用者验收，详见 `docs/验证记录.md`。
- 首版实现 Node.js原生后端 + 原生JS前端；聊天记录中的 Next.js/React 是技术建议。已有HTTP接口可供未来Next.js前端复用。
- v0.2 已有独立运输需求和报价表；仍按审核消息顺序保留同票事实版本。较早截图、矛盾信息及多票混合截图仍需人工确认，不能将新上传等同于最新业务事实。旧未分类记录暂不提供自动搬迁。
- 去重采取保守规则，不保证任意裁剪、OCR差异或不同截图顺序的完美去重。**只有时间没有日期**的内容不会当成唯一身份依据。
- 相关历史是关键词检索并限制扫描最近1000条，不是向量检索；超长客户历史的检索质量需后续增强。
- 截图中的每条消息关联本批全部截图，未提供单气泡坐标定位。
- 没有自动发送、客户合并、自然语言全库筛选、团队权限、定时跟进或云端托管。
- 草稿与截图保存在本机，删除草稿会删除其未归档截图；删除单条消息不自动删除原截图。磁盘没有额外应用级加密，建议使用设备全盘加密。
- 不提供实时运价、税率或HS编码确认，不自动承诺运输进度或DDP含税。

## 数据与备份

默认保存 `data/crm.sqlite`、SQLite WAL 文件及 `data/uploads/`。`DATA_DIR` 可调整位置；迁移时一并迁移数据库和截图。

**先停止应用，再运行** `npm run backup`。这会生成一致的SQLite快照和相应截图，备份目录自带恢复说明。将备份复制到安全位置。客户JSON导出仅含文字与截图标识，不含图片文件，不等同于完整备份。

源码交付包不包含密钥、运行数据库或任何真实客户截图。

## 访问方式

跨设备服务需另行部署：设置至少12位 `APP_PASSWORD` 与明确的 `APP_ORIGIN`，使用HTTPS反向代理和安全备份。当前版本不会公开发布。单用户密码不等同于团队账号体系。

## v0.3.0：数据库智库 · 微信群询价与报价历史

顶栏“数据库智库”用于人工维护的群聊历史，与每位客户的私有记忆分开保存。新建或选择微信群后，每次可上传该群最多10张截图（单张8MB、合计32MB），也可粘贴群聊原文；不同群分批导入，可以长期累计每天的记录。同名群不会自动合并，同名昵称也不自动合并为微信账号。群备注用于辨认不同群。

识别逐张进行，保留双方全部可读消息、发送者昵称、原文/中文、可见日期/时间、@对象、各产品的询价、报价和条件，随后进入持久化待审核草稿。看不清的身份或内容标为待核对。截图没显示完整日期时可手动填写聊天日期，不会把上传日期当作聊天发生日期。AI建议的询价/回复关联需逐项勾选确认；校对消息内容后旧建议停用，可先归档再从询价详情人工重新关联。未归档草稿可关闭后从“待审核导入”继续审核。

“产品询价”按每种产品独立显示状态。一条消息问多种产品时分别建立询价；明确金额/币种/单位的报价关联才计作已报价。“可以做”“稍后报价”“已私聊”和单独@是普通回复，不能清除待报价标记。每条关联标明回复者及是否@询价者；身份仍不确定时保持待核对。同群次日的报价可以关联到历史询价，不能跨群关联。**“尚未找到报价”仅表示当前已导入并确认的记录中未找到报价，不推断未上传的聊天或私聊是否已报价。**

“全部聊天”可搜索发送者、原文、中文及日期，原截图可查看。询价和普通聊天均保留，不只保存价格摘要。历史关联可人工添加/取消。消息校对保留旧版本，并使相关旧询价/报价关联失效或待复核；需重新确认后才计入当前报价。重复导入同一群的相同截图不会重复保存消息；相邻连续重叠采用保守去重，没有完整日期/时间的相似短句不擅自去重。所有历史可搜索、分页查看；AI关联建议只读取有限候选，未建议的记录可人工搜索关联。

右侧翻译/回复下方增加“智库 · 相似产品询价”：根据当前客户、当前运输需求及已识别的产品/别名检索已审核的群聊记录，不读取其他客户的私有聊天。可手动输入产品检索，或点击“从当前聊天智能提取产品并匹配”（会调用现有千问接口）。卡片显示历史询价人、回复者、群、日期、是否@、价格与完整条件，可查看全部来源或复制参考；不会自动报价、覆盖客户档案或自动发送。历史报价不等于当前有效价格或客户已接受，使用前须核对产品规格、数量、币种、费用范围和有效期。

智库保存在 `DATA_DIR/intelligence.sqlite`，截图在 `DATA_DIR/intelligence-uploads/`。标准备份同时包含智库数据库、归档/待审核截图、客户数据库及公共资料库；恢复时同时恢复这些数据库和图片目录，避免仅恢复客户数据库。现有客户数据库结构不变。真实群截图的识别、身份归属和报价关系需要用实际样本校对；自动化测试使用合成数据和模拟模型响应。

智库多图上传采用后台任务，避免长批次超过反向代理请求时限。可以关闭上传窗口，完成后从“待审核导入”继续；已完成的草稿和截图会持久保存。识别过程中的任务状态属于当前服务进程，如恰逢服务重启，请先检查待审核列表再决定是否重新上传。

浏览器回归可用 `node scripts/intelligence-test-server.mjs` 启动仅使用合成数据和模拟模型的隔离服务，再设置 `UI_INTELLIGENCE_TEST_URL=http://127.0.0.1:3121` 运行 `node scripts/intelligence-ui-check.mjs`。Playwright和Chromium为可选测试工具，不是应用运行时依赖。不要把合成测试服务作为生产服务。

## v0.3.1：图片识别结果兼容与字段错误修复

修复千问把可选数组、时间、语言标签或资料引用返回为null/不同结构时整张图片报“缺少有效字段”的问题。只兼容明确的类型差异，不补造原文、中文或事实；发送方不明时标unknown，仍需人工确认。发现必需字段或来源错误时，每个阶段最多尝试一次格式修复（会产生额外模型调用），固定已验证的消息表，不允许删减或改写已识别原文。鉴权、额度、网络超时和输出截断不会作为结构错误反复重试。失败提示指出具体字段，并持续显示在上传区，图片保留供重试。

每批客户记忆条目上限由40提升到400，仍逐项检查类型、来源索引和人工审核；不静默截掉长记录中的事实。无法读取的非聊天图片明确提示裁剪或填写原文，不生成演示聊天。

若图片原文、翻译及事实已验证，但后续公共资料库回复生成失败，保留待审核草稿和原图，停用未验证的自动回复。可先确认归档消息，再在右侧点击“按资料库更新回复”重试；成功后清除失败状态，原消息和事实保持不变。数据库智库、十图上传及客户记忆入口继续保留。回归使用合成模型响应；真实截图识别内容仍需人工核对。

## v0.3.2：产品检索词不再阻断图片识别

修复 `product_terms` 内的空项、对象或超长值导致整个图片分析失败的问题。该字段仅用于智库匹配：兼容字符串及明确的产品名称/别名对象，去重后最多保留16个有效检索词；无法解释的项跳过并显示提醒，不补造产品、不转成客户事实，也不为检索词错误额外调用模型。即使没有有效检索词，已验证的原文、中文和事实仍可进入人工审核，右侧沿用聊天/货物事实检索或手动输入产品。原文、翻译、身份和事实来源的必需校验不变，多图仍完整识别后统一审核，无数据库结构变更。回归使用模拟模型响应，真实原图仍需更新后重试。

## v0.3.3：相邻截图单条重叠去重

修复两张截图只重叠一条消息时无法去重的问题。客户聊天与数据库智库均在逐张转录后、生成摘要/事实/报价关联前合并重叠，审核窗口会提示合并数量，原截图与来源保留。匹配只比较相邻截图的尾部和头部，兼容换行、空格、全半角、弯引号、末尾句点及明确时间格式的差异，不根据中文翻译相似就合并，也不做数字、币种、否定词的模糊替换。

单条重叠需原文足够完整、发送方明确且没有时间冲突；“OK”“谢谢”等孤立短句、身份或文本不清楚的单条保留供核对。同一张图内真正重复发送的消息保持不变。分次上传的单条截图重叠还需双方都有完整日期和时间，仅有时分不推断为同一天；仍只在同一客户同一票、或同一群中复用。群聊产品、报价条件或@对象不同的条目不会被合并。无数据库结构变更，不批量清理已归档消息。测试使用合成转录，真实截图OCR差异仍需人工核对。

## v0.3.10：登录校验与密码重置

修复原生Nginx部署中所有访问共用代理IP计数的问题：仅在已配置站点且连接来自本机代理时，使用代理追加的最后一个有效客户端IP隔离失败次数；公网直连和无代理配置不信任转发头。错误次数只在一分钟窗口内累计，第五次错误进入一分钟冷却，返回准确的Retry-After，冷却期间仍不接受猜测密码。页面显示秒数倒计时，提交期间禁止重复点击。密码按配置原值精确校验，保留大小写和首尾空格，不再调用通用文字裁剪函数。

原生部署可在服务器执行 `python3 /opt/morocco-ai-crm/manage.py --reset-password`，交互式输入两次新密码（8—1000位，不回显）。管理工具更新私有app.env中的密码并随机轮换APP_SESSION_SECRET，保存权限600的旧配置备份并重启本服务，然后验证未登录保护、新密码实际登录及Cookie会话；验证失败恢复原配置并重启。既有客户、智库、截图和千问设置保留，即使重设为相同密码，旧Cookie也会失效，进程内错误次数清除。初始安装仍按原有12位规则引导，不将任何用户的真实密码写入源码。

## v0.3.11：图片临时断连恢复

针对图片识别中的 `UND_ERR_SOCKET` / `ECONNRESET` / `EPIPE`、HTTP流接收中断或缺少完整结束标记，客户图片分析及智库导入的当前请求最多自动重连一次。重连等待500毫秒，与首次请求共用原来的单次总截止时间，默认仍为120秒，格式修复仍为45秒；不会重新获得一整轮等待时间。鉴权失败、额度限制、HTTP错误、真正超时、模型JSON错误和输出长度截断不做网络重连。若仍失败，提示具体来源、网络错误、等待/接收阶段及是否已重连，截图留在页面，不保存半截结果。

客户和群聊截图均改为同一批内逐张处理，降低多模态并发连接压力；图片链路请求使用Connection: close，减少失效空闲连接复用。成功重连时只重读当前失败调用，不重跑该任务里已经完成的前面图片；关联建议阶段恢复也不重新OCR。全部消息和来源仍完整校验后才保存待审核草稿，去重、人工确认、群/客户隔离及引用范围保持。

智库上传窗口增加阶段和已用时间，自动重连会显示进度；审核提示记录本批发生的重连。一个失败请求的重连可能产生额外一次模型调用用量，导入窗口会说明。真实服务器到千问的持续网络故障仍会报错，此版本不把它隐藏成成功。测试用合成数据及本机真实断流HTTP服务，未使用生产密钥或付费图片请求。
