# crm.sogreat.cc 服务器安装包

适用目标：Alibaba Cloud Linux 4，root，已有Nginx官网。原官网sogreat.cc继续保留。此包不需要Docker，不包含密码、私钥、用户数据库或截图。

## 上传与安装

1. 独立安装包方式：将morocco-ai-crm-server.zip上传到服务器/root目录。
2. 在Workbench的Shell终端执行：

    crm_setup_dir=$(mktemp -d /root/crm-setup.XXXXXX)
    python3 -m zipfile -e /root/morocco-ai-crm-server.zip "$crm_setup_dir"
    python3 "$crm_setup_dir/morocco-ai-crm-server/install.py" --install

也可从本GitHub仓库的部署分支获取源码，解压后在项目根目录执行 `python3 deploy/native/install.py --install`。此方式不携带Node归档，安装器会从Node.js官方HTTPS地址取得固定版本并核对SHA256；不需要在服务器安装GitHub CLI或提供GitHub密钥（私有仓库则需由拥有访问权限的用户取得源码）。

安装会提示设置至少12位网页访问密码，输入不显示；密码不需要发到聊天里。包内带官方Node.js24.22.0 x64归档，并固定校验值；ARM64机器会从Node官网获取对应归档并验证固定SHA256。运行环境与应用放在/opt/morocco-ai-crm，不替换系统Node，也不安装Docker。

安装器先检查现有Nginx，寻找http层的独立*.conf包含目录；如果遇到已有非本安装器管理的CRM配置或客户数据库，会停止并保留。代码使用独立的moroccocrm系统用户运行，本机监听127.0.0.1:3010，数据库和截图位于/var/lib/morocco-ai-crm。密码只保存在服务器/etc/morocco-ai-crm/app.env（root可读）。Nginx只新增crm.sogreat.cc配置，并测试后reload；测试失败会恢复该新增配置之前的状态。初始HTTP仅开放证书校验路径，登录须等待HTTPS。

若旧版安装停在启动检查，日志仅有 `Started` 和 `Deactivated successfully`，原因是Node入口判断与 `current` 符号链接不一致。新版systemd使用解析后的实际版本文件路径。取得新版安装器后运行 `python3 deploy/native/install.py --resume`，可修复本项目服务并继续创建尚未生成的CRM站点配置；保留现有密码和客户数据。它拒绝覆盖已有站点配置或其他程序的服务文件。该操作只恢复中断的首次安装，不能作为应用升级工具。

## DNS与HTTPS

在sogreat.cc的DNS管理中新增A记录，主机crm，值8.209.58.190，TTL默认；保留现有@、www及其他记录。确认没有冲突的crm/AAAA记录，等待解析生效后执行：

    python3 /opt/morocco-ai-crm/manage.py --https

此阶段在独立venv从官方PyPI HTTPS地址安装固定版本Certbot 5.8.0，禁用pip配置文件、镜像环境覆盖及下载缓存，仅接受wheel并保留TLS与包校验。申请Let's Encrypt证书需接受该CA服务条款，安装命令会自动进行ACME注册（不提供邮箱）。证书仅用于crm.sogreat.cc，现有官网证书配置不变。申请成功后配置HTTPS代理及该证书的每日自动续期检查。真实证书签发需DNS和80/443公网可达；实际结果以运行输出为准。

旧版若从服务器默认HTTP镜像安装了证书工具，可用新版安装器执行 `--repair-certbot`。它暂停本项目续期定时器，在全新venv通过官方HTTPS源安装并验证版本，随后切换本项目续期服务并恢复定时器；不重用原venv的程序，也不改动现有证书、官网、应用密码或客户数据。安装失败时定时器保持暂停，修复后可重试。

若从聊天或其他网站点击链接时出现“不允许跨站请求”，从新版完整源码目录执行 `python3 deploy/native/install.py --repair-navigation`。修复仅允许浏览器顶层GET导航打开公开首页；跨站接口、登录提交和嵌入仍被拒绝。安装器核对新旧源码哈希，在配置目录保留首次修复前的源码，只替换本项目服务文件并重启本项目；健康检查失败会恢复替换前文件。不改动密码或客户数据。

## 状态、配置与备份

    python3 /opt/morocco-ai-crm/manage.py --status
    python3 /opt/morocco-ai-crm/manage.py --backup

备份命令会暂停本项目服务，以应用用户制作数据库和截图快照，然后恢复先前正在运行的本项目服务；备份位于/var/lib/morocco-ai-crm/backups/。不会停止Nginx或官网。请另行将备份保存到安全位置。

v0.2.1增加网页登录后的“千问 API 设置”，直接入口 `https://crm.sogreat.cc/#settings`。Key只保存在服务器数据目录的私有配置文件，不回显、不进入客户导出；网页保存立即生效，环境变量仍可作为默认配置。测试连接不会建立客户档案，但会产生少量真实模型调用用量。固定示例不代表真实识别。

已部署v0.2.0时，取得新版完整源码，在项目目录运行 `python3 deploy/native/install.py --upgrade`。升级先运行项目测试，再备份客户数据库及截图，建立独立v0.2.1版本目录，切换并验证本项目服务；失败会恢复原代码与服务配置。保留app.env、数据目录、现有密码、官网Nginx配置及证书，不重复执行初始安装。升级后管理脚本仍位于 `/opt/morocco-ai-crm/manage.py`。

当前升级目标为v0.2.2，支持从v0.2.0/v0.2.1升级。新增自定义回复的多语言选择与复制，以及全部记忆/本次图片总结分区；数据库结构不变，保留已填写的 `qwen-settings.json` 和客户资料。执行同一个 `--upgrade` 命令即可，不用重新填写Key。

最新目标为v0.2.3，也支持从v0.2.2升级：新增回复区临时收起按钮，以及记忆逐项原文/中文解释。继续使用 `--upgrade`，保留数据库、图片、Key和密码，不改变数据库结构。旧外文资料的中文通过现有千问接口按需补充并作进程内缓存，不回写原始事实。

当前最新目标v0.2.4增加所有聊天共用的“数据库参考”，支持从之前v0.2版本通过 `--upgrade` 更新。新资料库为数据目录内独立的 `company-knowledge.sqlite`，无需修改原客户数据库结构，旧代码回退后此文件仍保留。标准备份现在同时包含资料库；恢复时一并复制该文件。没有预置业务资料，升级后在网页登录并自行录入。

最新修复v0.2.5支持一次10张截图，多图逐张转录后汇总，防止汇总时丢失已识别消息。从本次新版源码运行 `python3 deploy/native/install.py --upgrade`，可由v0.2.4及之前版本升级；不要运行旧的 `/opt/morocco-ai-crm/manage.py --upgrade` 来获取新版源码，它不是下载更新器。升级自动测试、备份、切换代码并重启服务，健康检查失败回退原版本。数据库、截图、Key、密码、证书及官网配置保留。不需要系统npm，使用现有安装记录中的Node运行测试。完成后执行 `python3 /opt/morocco-ai-crm/manage.py --status`，应显示版本0.2.5，并在浏览器强制刷新。

v0.2.6将AI回复整个模块移到右侧，客户记忆改为左侧每个客户条目上的按钮及弹窗。手机导航为客户、对话、回复。支持从v0.2.5及之前v0.2版本使用新版源码的 `--upgrade` 更新，自动备份、重启并检查0.2.6版本；无需迁移或删除现有数据库，不改动密码、Key及客户记录。

本安装包初始部署不覆盖已有安装。安装完成后如需升级，请先备份并单独准备迁移，不能删除数据目录重装。

## 本次验证范围

- Node.js官方SHA256校验、归档解压及重复缓存校验通过；项目28项测试在24.22.0全部通过。
- 独立Nginx实例真实HTTP/HTTPS代理验证通过：测试官网保留、HTTPS前CRM登录关闭、受信测试证书校验、登录/Secure Cookie、固定草稿审核、运输需求、客户记忆、报价与导出。
- Nginx配置目录识别覆盖主配置http层、相对包含路径及常见面板目录；拒绝将server层include当作vhost目录。
- 服务器现场已通过官方Node下载校验和28项测试；首次systemd启动遇到上述入口路径问题。修复后的实际文件启动、状态接口及恢复流程的文件保留检查已在开发环境通过；真实systemd恢复、生产证书签发及公网登录需要继续现场验收。测试证书和测试私钥不包含在此安装包中。

v0.3.0新增“数据库智库”，保存微信群完整聊天、询价、报价、发送者及@关系，并在右侧回复下方检索相似产品历史。支持从v0.2.6及之前版本使用新版源码的 `--upgrade` 更新。新建独立intelligence.sqlite和intelligence-uploads，不变更原客户数据库结构。新版标准备份包含智库及全部来源图片；恢复时也需恢复这两项。升级检查目标为0.3.0，失败仍回退原代码，客户资料、群聊记录、Key、密码、证书保留。识别和智能匹配使用已配置的千问接口，导入建议需人工审核确认。
